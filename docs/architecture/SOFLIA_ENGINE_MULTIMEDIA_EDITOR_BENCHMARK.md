# Benchmark, factibilidad web y ledger de fuentes

> Artefacto 2. Investigación externa consultada el **2026-09-26**. Las URLs son evidencia primaria u oficial salvo indicación expresa.

## 1. Criterio de selección

Se eligieron referentes por la decisión que habilitan, no por popularidad:

- **HyperFrames y Remotion**: documento serializable, preview y render determinista.
- **Canva y CapCut Web**: baseline de creación rápida en navegador para no especialistas.
- **Premiere y Resolve/Fairlight**: semántica profesional de edición y audio; son techo de referencia, no backlog automático.
- **GrapesJS**: separación modelo/vista y propiedades expuestas para HTML visual.
- **W3C/MDN, ffmpeg.wasm y Supabase**: factibilidad, aislamiento y límites técnicos.

VEED, Descript, Clipchamp, Kapwing, Runway, Figma, Photoshop, Affinity, Webflow, Framer y Blender se revisaron solo como universo de contraste. No se les asigna `Sí`/`No` detallado sin evidencia primaria suficiente; se conserva `No verificada`.

## 3. Hechos, inferencias y recomendaciones

- **HECHO VERIFICADO**: HyperFrames define video como HTML y renderiza mediante seeks deterministas por frame (SRC-E01/E02).
- **HECHO VERIFICADO**: Remotion recomienda pasar el mismo payload JSON serializable al Player y al render server-side (SRC-E04/E05).
- **HECHO VERIFICADO**: WebCodecs expone codecs en Window/DedicatedWorker, pero no resuelve contenedores; requiere mux/demux y soporte comprobado en runtime (SRC-E06/E07).
- **HECHO VERIFICADO**: ffmpeg.wasm fue muy inferior a FFmpeg nativo en el benchmark publicado por su propio proyecto; no debe asumirse adecuado para renders largos (SRC-E10).
- **INFERENCIA TÉCNICA**: WebCodecs + Mediabunny es adecuado para thumbnails, waveform/probes y proxies pequeños, pero el render canónico debe permanecer backend/HyperFrames/FFmpeg.
- **RECOMENDACIÓN**: adoptar semánticas profesionales solo cuando reduzcan trabajo frecuente de cursos: ripple, waveform, loudness, presets, captions y reemplazo de assets antes que multicam, tracking o composición 3D.

## 5. Modelo de puntuación

Puntaje base:

`2×valor + 2×frecuencia + 2×reducción manual + automatización + aprovechamiento arquitectónico − complejidad − seguridad − divergencia preview/render − dependencias`.

Rango teórico: -18..39. Umbrales orientativos: P0 ≥ 28 o override por integridad/seguridad; P1 20..27; P2 12..19; P3 1..11; no recomendada ≤ 0. Los factores positivos principales pesan doble porque el producto debe optimizar flujo educativo. Un riesgo de pérdida de datos, aislamiento, publicación o paridad puede elevar a P0 aun con score menor.

## 7. Targets recomendados de plataforma

Estos son objetivos propuestos, no requisitos confirmados:

- Desktop: Chrome/Edge evergreen, últimas 2 versiones, objetivo principal. Firefox/Safari: lectura y edición base solo tras matriz de codecs/runtime. Tablet: revisión, texto, captions y ajustes; no timeline profesional completa. Móvil: preview/aprobación, no autoría multipista.
- Hardware objetivo: 4 núcleos modernos, 8 GB RAM mínimo; 16 GB recomendado, GPU con WebGL2. Validar por telemetría; no bloquear por marca/modelo.
- Composición: 1080p SDR/Rec.709, 25/30 FPS primarios; 24/60 condicionados. Límite actual confirmado: 10 min, 500 clips, 32 tracks; objetivo UX inicial más conservador: 150 clips, 12 tracks, máximo 4 decodificadores de video simultáneos.
- Entrada objetivo: MP4/H.264/AAC, WebM/VP9/Opus, PNG/JPEG/WebP, WAV/MP3/AAC/Opus, SRT/VTT. Detectar por contenido, no extensión. MOV/HEVC/HDR: transcodificar backend o rechazar explicando el motivo.
- Salida: MP4 H.264/AAC como baseline; WebM opcional. El navegador no es la ruta canónica de export.
- Online-first con journal local cifrado/limitado, reanudación de uploads y rebase OCC. No prometer edición offline completa.
- Teclado completo para timeline/playhead/selection; foco visible, nombres accesibles, dialogs con focus trap, reduced motion en UI, captions, Unicode/RTL y formateo local de timecode/números.

## 8. Factibilidad por lugar de ejecución

| Capacidad                            | Lugar recomendado                                        | Justificación                                                                     |
| ------------------------------------ | -------------------------------------------------------- | --------------------------------------------------------------------------------- |
| Operaciones/documento/undo           | Navegador main thread + Worker para diffs grandes        | Contratos pequeños y feedback inmediato; no bloquear UI con validaciones pesadas. |
| Thumbnails/waveform                  | Worker + WebCodecs/Mediabunny; fallback backend          | Frames/audio transferibles; soporte de codec se prueba en runtime (SRC-E06-E08).  |
| Audio interactivo                    | Web Audio/AudioWorklet                                   | Graph y automatización de parámetros (SRC-E09).                                   |
| Loudness/denoise/normalización final | Backend FFmpeg                                           | Reproducibilidad y costo; ffmpeg.wasm no es ruta de producción (SRC-E10).         |
| Transform/crop/text                  | DOM/Canvas/WebGL según efecto                            | DOM preserva texto; WebGL solo donde el shader agrega valor.                      |
| Color/chroma/masks                   | WebGL2 preview + mismo shader render                     | Evita matemáticas divergentes; WebGPU no es requisito.                            |
| Render final                         | HyperFrames + FFmpeg backend/cloud                       | Seek determinista y assets congelados (SRC-E01-E03).                              |
| HTML editable                        | iframe sandbox + canal tipado; renderer backend idéntico | Aislamiento del contenido activo y contrato serializable (SRC-E20-E23).           |

WebGPU no debe formar parte del baseline. Solo merece prototipo si un shader/efecto medido excede WebGL2 y el soporte objetivo lo permite.
